## 2. 문장별 방어

### 2.1 "LangGraph" — ⚠️ 재프레이밍 (최우선 준비)
실제 구현은 Claude Code 플러그인 기반 lifecycle agent 4종. 면접 전 **LangGraph로 동일 파이프라인을 재구현**해서 "짜 본 사람의 언어"를 확보할 것.

| 실제 구현 (rtl-agent) | LangGraph 대응 개념 |
|---|---|
| setup→execute→analysis→debug 4단계 agent | `StateGraph` 노드 4개 + 엣지 |
| rule 특성별 분기 | conditional edge (라우팅 함수) / `Command(goto=...)` |
| 위반 유형별 전문 Agent 분담 | supervisor 패턴 (`langgraph-supervisor`) |
| 검증 Agent 근거 교차 확인 | reflection 노드 (생성→평가→재시도 루프) |
| 불확실 건 설계자 이관 | `interrupt` (HITL) |
| 세션 상태·이어하기 | checkpointer (`SqliteSaver`) + `thread_id` |
| MCP 도구 (kb-mcp, shell-bridge) | `langchain-mcp-adapters` → `ToolNode`/`bind_tools` |

- 예상 꼬리: "State 스키마?" → TypedDict: `violations/classified/evidence/confidence` / "conditional edge vs Command?" / "checkpointer 왜 필요?" → 장시간 EDA 실행 중단·재개 + HITL interrupt / "왜 LangGraph?" → 폐쇄망 self-host + 그래프 명시적 제어 흐름(감사 가능) + HITL 지원 / "LangChain과 차이?" → 체인(선형) vs 상태 그래프(루프·분기·재개)
- **[v3 타임라인 이점]** Agent 착수 = 2025.09 → LangGraph 성숙기(1.0 전후)·MCP 공개(2024.11) 이후라 "**처음부터 LangGraph+MCP 표준으로 설계**"로 답변 단순화. v2의 "자체 오케스트레이션→마이그레이션" 연대기 폐기. 버전 질문엔 "0.6 계열로 시작해 1.0 안정화를 따라갔다" 수위
- 폐쇄망 트레이싱: "LangSmith 없이 관측은?" → 자체 콜백 로깅·파일 트레이스
- 최후 폴백(정직 수렴): "사내 플랫폼 제약에 맞춘 오케스트레이션 계층을 직접 설계·구현했고, 동일 아키텍처를 LangGraph로 재구성해 시연 가능"

### 2.2 "검증 도메인별 전담 Agent 3종 + 검증 Agent" — ⚠️ 재프레이밍 (v6 상향)
**사실관계**: 실제 rtl-agent는 lifecycle 4단계(setup→execute→analysis→debug). 서류(v6)는 "검증 도메인별 전담 Agent 3종(Lint·CDC·RDC류)+검증 Agent"로 재서술 — 사용자 방침: Multi-Agent 구조가 핵심이고 도메인 용어 자체는 팔지 않음.
- 답변 골격: "각 Agent가 하나의 검증 영역(rule 체계·판정 기준·참조 문서가 서로 다름)을 전담하고, 공통 검증 Agent가 판정-근거 정합을 교차 확인" — 도메인을 물으면 "Lint·CDC·RDC 같은 정적 검증 계열"까지만
- **P0 재구현과 정합**: LangGraph 재구현 시 supervisor + 도메인별 worker 3종 + reflection 노드로 구현하면 서류 구조와 1:1 (§2.1 표의 "위반 유형별 분기"가 이 라우팅)
- 왜 도메인별 분리인가: ① rule 체계·지식베이스가 도메인마다 달라 프롬프트·검색 필터를 특화 ② 컨텍스트 격리 ③ 도메인별 정확도를 따로 측정·개선
실제 4종 경험 기반 답변 가능한 것들:
- "왜 멀티인가?" → ① 컨텍스트 격리(대용량 로그 오염 방지) ② 역할별 도구 권한 최소화(execute만 셸) ③ turn/비용 상한 역할별 차등
- "Agent 간 정보 전달?" → 구조화된 핸드오프(요약 상태만), 원본 로그는 경로 참조
- "실패 사례?" → 오분석 누적 → 검증 Agent(결론–근거 정합 확인) + 불확실 건 이관으로 해결한 서사
- "불확실 판단 기준?" → 근거 출처 등급(툴 DB>사내 가이드>벤더 매뉴얼>LLM 추론)과 검증 Agent 통과 여부 — 임계 미달 시 자동 이관 (구두 카드: 신뢰도 스코어링)

### 2.3 "Vector DB·정형 DB·Graph DB 분리 적재 RAG 지식베이스" — ✅ 실화
- v4 기술셋에 **Milvus·PostgreSQL 명기** (실사용 — 폐쇄망 self-host·HNSW·컬렉션 스키마 / 판정 이력 정형 저장). Graph DB만 제품명 미기재 유지(§2.9)
- 분리 기준 답변: "무엇을 묻느냐"로 저장소를 고름 — 의미 검색(매뉴얼·가이드)=Vector / 정확 조회(rule ID·판정 이력)=정형 / 관계 추적(모듈·신호)=Graph. "전부 Vector에 넣으면 왜 안 되나?" → 정확 조회를 유사도 검색으로 하면 재현 불가·중복/버전 충돌, 관계 multi-hop은 임베딩으로 표현 불가
- 꼬리: chunking(rule 단위+메타데이터 필터) / 임베딩(폐쇄망 오픈소스 bge/e5 계열) / RAG 품질 평가(판정 완료 위반 golden set 정확도)

### 2.4 Transformer 이해 — 🔴 자격요건이라 반드시 질문됨
self-attention 직관, decoder-only 구조, KV cache(긴 로그 비용의 근원 → "로그를 요약·구조화해 컨텍스트 절감"으로 실무 연결), context window와 chunking, temperature=0·구조화 출력(재현성).
**파인튜닝 vs RAG 판단 기준** (반드시 나옴): 자주 바뀌는 지식은 RAG(가이드 개정 대응), 형식·판단 패턴 내재화는 파인튜닝 — "그래서 지식은 RAG로, SystemVerilog 이해·분류는 파인튜닝으로 역할을 나눴다"가 v3 2-프로젝트 구성 그 자체.

### 2.5 Prompt Engineering — ✅ 실화 (서류 문구 없음, 구두 카드)
- rule 유형별 대표 위반·판정 예시 few-shot, JSON 스키마 고정 출력(판정/근거/신뢰도/출처) → v3의 "판정·근거 요약"이 그 산출물
- 꼬리: "프롬프트 버전 관리?" → 파일 분리·Git / "실패 케이스?" → 오판정 사례를 예시·KB로 환류

### 2.6 "SystemVerilog 특화 LLM 파인튜닝" (프로젝트 2) — ⚠️🔴 전면 준비 (v3 승격: 한 줄 PoC → 독립 프로젝트)
**서류 주장**: 사내 RTL 코드·리뷰 이력에서 코드-설명 학습쌍 약 3만 건 생성·정제(전문가 검수) / 폐쇄망 GPU LoRA 학습·평가 파이프라인 / 평가셋 정답률 60%→80% / Agent 분석 엔진으로 편입 (2025.01~2025.09).

**논문 그라운딩** (실존 논문 — 답변의 뼈대, "업계 검증된 접근을 사내 데이터로 재현" 포지션):
| 논문 | 가져온 것 |
|---|---|
| **ChipNeMo** (NVIDIA, arXiv 2311.00176) | 칩설계 도메인 적응 LLM의 산업 선례 — 도메인 SFT·도메인 검색. "NVIDIA가 EDA 스크립트·버그 요약에 적용" 카드 |
| **RTLCoder** (arXiv 2312.08617) | instruction-code 쌍 **27k 자동 생성**·품질 필터 → "약 3만 건" 규모의 근거. 7B 파인튜닝으로 GPT-3.5 초과 |
| **CodeV** (arXiv 2407.10424) | **실코드에서 역방향으로 설명 생성**(multi-level summarization) → "사내 RTL에서 코드-설명 쌍 생성" 방법론의 근거 |
| **VerilogEval** (NVIDIA, ICCAD 2023) | Verilog 평가 벤치마크 — "사내 평가셋 구축"의 원형 |
| **VeriCoder** (arXiv 2504.15659) | Qwen2.5 + LoRA rank 16 — 하이퍼파라미터 현실감 |

**확정 서사(암기, v7.2 — 사용자 확정 팩트)**: ① 2025년 초 LLM 도입 검토에서 범용 모델이 SystemVerilog 관례(클록 도메인·리셋 계열·generate 구문·합성 가능성)를 오독하는 걸 확인 ② 베이스 = **Qwen2.5-Coder-7B**(2024년 말 공개, 폐쇄망 반입 가능 오픈 웨이트·코드 특화 — gpt-oss는 2025.08 공개라 당시 선택지에 없었음) ③ **도메인 코퍼스**: 사내 RTL repo + Lint·CDC 등 정적 검증 툴 문서·rule 정의 + 설계 스펙 문서 — 중복 제거(해시+유사도)·컴파일 검증 필터로 고품질만 선별 ("양보다 품질" — 고품질 소량이 대량 전체보다 낫다는 것이 업계 정설) ④ **2단계 학습**: 도메인 적응 사전학습(DAPT, LoRA 기반 continued pretraining으로 설계·검증 지식 주입) → 판정·설명 태스크 instruction 튜닝(SFT) — "문법이 아니라 칩 설계 전반을 이해"의 기술적 실체, ChipNeMo와 동일 구조 ⑤ **합성 데이터**: 사내 공용 대형 모델(70B급)을 teacher로 코드-설명·판정 쌍 자동 생성, 품질 필터 통과분만 사용 ⑥ **인프라**: A100 80GB×4 단일 서버, 학습→평가→리포트 자동화(실험 주기 주1→일1) ⑦ 평가: 이해·분류 태스크 전문가 채점 60%→80%, **teacher로 쓴 그 대형 모델과 비교해 1/10 크기로 동등 성능** → vLLM 자체 서빙.

**본인 이해용 — 합성 데이터·품질 필터 메커니즘 (먼저 이걸 소화할 것)**:
- **SFT** = Supervised Fine-Tuning = "질문→정답" 쌍으로 추가 학습(=instruction 튜닝, 같은 말). 2단계 = ① 문서·코드 원문을 읽혀 지식 흡수(도메인 적응 사전학습) → ② 질문-답 쌍으로 일 시키는 훈련(SFT)
- **합성 데이터 생성** = 사람 대신 큰 모델에게 라벨을 시키는 것: 사내 코드 조각 → 70B에 "이 모듈 설명해라/이 위반 판정해라" → 답을 (코드, 설명) 쌍으로 저장 → 7B 학습. 선례: Alpaca(GPT로 5.2만 건), RTLCoder(2.7만 쌍), CodeV — 표준 기법
- **품질 필터 3단**: ① 규칙 검사(형식 불량·중복·과단문 제거) ② LLM 재검증 — 생성된 설명을 모델에 다시 주고 "코드와 일치하나" 채점(LLM-as-judge) ③ 사람 샘플 검수(~10%만, 오답률 기준 미달 배치는 폐기)
- **90% 절감 산정**: 전문가 수작업 = 쌍당 ~10분 × 수만 쌍 = 수천 시간 vs 자동 생성 후 사람 몫 = 필터 기준 설계+10% 샘플 검수 → 공수 ~1/10. "추정 공수 대비"임을 같이 말하고, 품질 반박엔 "+6%p ablation이 품질의 증거"로 회수

**예상 꼬리질문 + 답변 수위**:
- "왜 LoRA, full FT 아니고?" → A100×4 자원 제약 + 도메인 태스크 특화 + 베이스 동결로 범용 능력 보존(catastrophic forgetting 회피). DAPT도 LoRA 기반 continued pretraining으로 수행
- "DAPT 데이터 규모·하이퍼파라미터?" → "코퍼스 수 GB(수억 토큰) 수준, LoRA r=16 계열, 러닝레이트는 사전학습 단계를 SFT보다 낮게" 수위 — 정확한 수치 요구엔 "내부 기록 기준이라 범위로만" 정직 컷
- "DAPT하면 원래 능력 잊지 않나?" → LoRA라 베이스 가중치 동결 + 일반 코퍼스 소량 혼합(replay)으로 완화, 범용 태스크 회귀 확인
- "왜 Qwen2.5-Coder?" → 당시(2025 초) 반입 가능한 오픈 웨이트 중 코드 특화 최상위, 7B가 A100×4에서 학습·서빙 모두 감당 + 대형 모델 대비 1/10 크기 스토리. (gpt-oss는 2025.08 공개 — 시점상 선택지 아니었음을 아는 것 자체가 방어)
- "정답률 80%의 정의?" → §3 참조. "생성 pass@k가 아니라 이해·분류 채점이라 개선 폭이 큼"
- "데이터 품질은 어떻게 담보?" → 자동 생성분을 전문가 샘플 검수 + 오답 사례 정기 리뷰(서류 소통 불릿)로 기준 개선
- "서빙은?" → v6 서류에 **vLLM 명기** — "파인튜닝 모델은 폐쇄망 GPU 서버에 vLLM으로 직접 서빙(PagedAttention·동시 요청 배칭 때문), 대규모 공용 LLM 인프라는 플랫폼 조직 소관"으로 이원화 답변. vLLM 기본기(continuous batching·OpenAI 호환 API) 학습 필수 |
- "지금도 쓰나?" → "Agent의 분석 엔진 한 축으로 편입, 불확실 건은 상위 LLM·설계자로 폴스루" (drop 아닌 라우팅 논리 유지)
- **P0 미니 재현**: VerilogEval/RTLCoder 공개 데이터로 Qwen2.5-Coder-1.5B급 LoRA 1회 학습+평가 (PEFT, 사양 낮으면 QLoRA) — "돌려본 사람의 언어" 확보 — 1~2일

### 2.8 "Perforce submit 시 Airflow에서 Agent 분석 자동 실행" — ⚠️ 재프레이밍 (v6 신규 표현, 과도 강조 금지)

- Skill 플랫폼(담당업무): Next.js+PostgreSQL, Infra 조직과 권한·보안 협업 — ✅ 실화
- **n8n·Dify 셀프서비스 환경(담당업무·항목3)**: 구도 = "코어 파이프라인은 LangGraph 직접 구축 + 현업의 간단한 자동화는 노코드 셀프서비스로 위임 → 1000명+ 확산의 메커니즘". 구체 사례 답변 준비: ① n8n — 오판정 리뷰 결과 취합→지식베이스 반영·주간 리포트 발송 워크플로 ② Dify — 설계 가이드 Q&A 챗봇을 현업이 직접 구성하도록 템플릿 제공. 꼬리 "그럼 LangGraph는 왜 직접 짰나?" → "판정 파이프라인은 신뢰성·제어 흐름이 생명이라 코드 레벨 제어가 필요, 현업 편의 자동화는 노코드가 적합 — 도구를 용도로 구분"

### 2.9 "회로 연결 정보는 Neo4j" — ⚠️ **P0 필수 (v6에서 실명 기재로 전환)**

## 4. 리스크 Q&A 스크립트

### 4.1 "해외 연구소에 정확히 무엇을 횡전개했나?"
사실 관계: **3곳 횡전개·현지 트레이닝은 SoC 설계 통합환경(방법론)** 실적(담당업무 2블록). Agent·Skill 플랫폼은 사업부 단위. "설계 통합 방법론을 해외 3개 연구소에 전파하며 1년+ 트레이닝했고(3주 현지 출장), 그 채널 위에 Skill 플랫폼을 얹어 사업부 500명+로 넓혔다" — 구분해 말하면 모순 없음.

### 4.2 "후공정(P&T) 도메인 경험이 없는데?"
정면 인정 + 전이: ① 반도체 지식베이스(rule/매뉴얼/판정 사례) RAG 구조화 경험은 공정 지식베이스와 동형 ② 비전공 현업 대상 AI 서비스 운영 경험 ③ HBM은 설계-후공정 접점(base die·TSV·적층 테스트)이라 로직 설계 이해가 자산 ④ MES/FDC는 학습 중 — 용어 선행 학습(§4.6).

### 4.3 "얼마 전 신입으로도 지원했던데?"
"설계 직무로 지원했으나, 실제 경력의 중심이 AI 기반 설계 자동화·Agent 개발이라 AI/DT가 정확한 매칭이라 판단해 경력으로 재지원했다" — 일관성 + 회사 지원 의지의 근거.

### 4.4 "삼성에서 잘하고 있는데 왜 이직?" + "우리 회사 비전이 뭔지 아나?" (구두 전용)
**비전 상식(서류에 인용함 — 반드시 숙지)**: "풀 스택 AI 메모리 크리에이터" — 곽노정 CEO가 SK AI Summit 2025(2025.11)에서 선포. 기존 '프로바이더(고객이 원하는 제품을 적시 공급)'에서 '크리에이터(고객 문제를 함께 해결하는 Co-Architect·생태계 기여자 Eco-Contributor)'로 진화 선언. 라인업 3종: 커스텀 HBM · AI-D램 · AI-낸드. 내 연결 논리: "고객의 문제를 함께 푼다 = 내가 현업 곁에서 Agent를 만들어 온 방식 — 그 방식이 회사 차원의 방향이 된 곳".
지원동기 문단과 동일 축으로 구두 답변: "사업부 최초로 LLM Agent를 실과제에 적용하는 과정을 주도하며 AI Agent 개발이 커리어 중심임을 확신했다. 현 소속은 설계 방법론 조직이라 AI는 '수단'의 위치 — SK하이닉스 AI/DT는 Agent가 '본업'이고, 공격적 증설로 커지는 제조 현장 전체가 무대라는 스케일" — pull 중심, 전 직장 비방·기밀 금지, 연봉 먼저 안 꺼냄. ("사업부 최초"는 서류에서 삭제됐으므로 구두에서만, "최초 사례로 알고 있다" 수위. 지원동기의 "신규 후공정 기지"는 청주 P&T7 착공 등 공개 사실 — 구두에서 구체 언급 가능)

### 4.5 압박: "LangGraph 실코드를 얼마나 짰나?"
재구현 완료 전제: "lint 파이프라인을 StateGraph+supervisor+interrupt+SqliteSaver로 구성했다" — **P0 완료 전엔 이 어휘 금지.**

### 4.6 P&T 용어 학습 (v6.5: 서류는 평이화 완료 — "검사 판정·설비 알람·진짜 불량"만 잔존, 아래는 구두 학습용)
**⚠️ 용어 검증 결과(2026-07-06)**: 과검·미검·가성불량은 실제 업계 용어(과검=1종 오류=가성불량, 미검=2종 오류). **"가성 알람"은 표준 용어 아님(가성불량+알람 혼합 조어 — 서류에서 삭제됨). FDC 헛경보는 "오알람/False Alarm"으로 말할 것.**
- P&T 흐름 한 줄: WT(다이별 전기 테스트→fail bitmap→redundancy repair) → PKG(절단·TSV 적층·MR-MUF) → PKT/TDBI(패키지 테스트·burn-in·bin 분류) → Module(DIMM 조립·실장 테스트)
- **과검(overkill)** = 양품을 불량 판정(수율·매출 손실) / **미검(underkill)** = 불량을 양품 판정(고객 유출·품질 사고) / **오알람(False Alarm)** = FDC가 정상 변동을 이상으로 오탐 → 엔지니어 triage 낭비·진짜 이상 매몰
- 전이 3축: ① 문제 동형성 — false violation과 오알람·과검은 "rule 기반 대량 판정 + false 다수 + triage 병목" 구조 동일 (서류의 "문제없는 건이 대량으로 섞여 있지만 진짜 불량을 놓치면 품질 사고" 문장이 이 구조) ② DFT가 다리 — WT/PKT가 구동하는 scan·BIST·repair는 설계 단계 삽입 구조 ③ HBM base die는 로직 다이
- 갭 정직 인정: FDC trace(시계열)·wafer map(공간 패턴)은 새로 배울 영역 — "도메인 데이터 구조와 현업 언어의 빠른 흡수는 설계 도메인에서 한 번 해봤다"

### 4.7 "LLM 경력이 2년이 안 되지 않나?" (v3 타임라인 — 신설)
서류상 LLM 프로젝트는 2025.01~현재 = 약 1년 6개월. JD 필수는 "**Python 기반 데이터 분석 및 LLM 애플리케이션 개발** 경력 2년 이상" — 답변 골격:
- "Python 기반 개발·데이터 분석은 3년 5개월 전체(자동화 방법론 단계 포함)이고, 그 위에서 LLM은 2025년 초 파인튜닝부터 Agent 프로덕션 운영까지 **풀사이클을 압축 수행**했다"
- 밀도로 보강: 파인튜닝(데이터 구축→학습→평가)·Multi-Agent 설계·RAG 3원 저장소·MCP 연동·CI/CD 배포·정규 절차 편입 — "연차가 아니라 커버리지"
- 서류에서 "LLM 2년"을 주장하지 않았으므로 과장 리스크 없음. 먼저 변명하지 말고 물어보면 위 골격.

### 4.8 "이 직무의 KPI가 뭐라고 생각하나?" (신설 — 직무 이해 어필 카드)
JD 문구가 아니라 현장 지표로 답한다:
- **P&T 현장 KPI**: ① 수율(최상위) ② 품질 — **과검(overkill) 최소화·미검(underkill) zero** ③ TAT/cycle time(고객 납기 직결) ④ 설비 가동률(OEE)·오알람(False Alarm) 대응
- **AI/DT 조직의 KPI**(현장 KPI에 기여하는 방식): ① 판정·분석 **자동화율** ② AI 판정 신뢰성 — 특히 **미검 방향 오류 zero** ③ 분석 리드타임 단축 ④ **현업 정착** — 일회성 PoC가 아니라 정규 프로세스 편입·사용률 (SK 사례: 가우스랩스 가상계측 도입→공정 산포 21.5% 개선처럼 "지표로 말하는 AI")
- **내 성과가 같은 구조**: 75% 자동화=자동화율·공수 절감 / 유출 0건=미검 zero 원칙 / 리뷰 TAT 50%↓=TAT / 정규 검증 절차 상시 운영=정착 — "설계 sign-off에서 이 KPI 체계로 운영해 봤고, P&T의 과검·오알람 문제에 같은 체계를 적용하겠다"
- 한 줄 마무리: "AI가 아무리 정확해도 **미검을 내면 신뢰를 잃고, 현업이 안 쓰면 KPI가 아니다** — 그래서 보수적 이관 설계와 정규 절차 편입을 처음부터 목표로 했다"
