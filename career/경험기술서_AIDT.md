## 제출용 본문

```text
[LLM 기반 RTL Sign-off Multi-Agent 시스템 개발·운영 — 사업부 최초 실과제 적용, 500명+ 서비스 확산]

(역할) LangGraph 기반 Multi-Agent 아키텍처 설계·백엔드 개발, RAG/Vector DB 구축, MCP 연동, 운영·확산 주도

RTL Sign-off는 수백 종 violation rule 이해를 요구하고, false violation이 섞인 리포트 분석에 설계 리소스를 소모시켰습니다.

이를 풀기 위해 Supervisor가 rule 특성별로 전문 Agent를 라우팅하는 Multi-Agent 구조를 LangGraph로 설계했습니다. 구조적 판정이 가능한 rule은 Tool DB 기반 deterministic 분석으로, 설계 의도 해석이 필요한 rule은 RAG Agent·LLM 추론으로 분기하고, Critic Agent의 교차 검증으로 오분석 누적을 차단했습니다. 설계 가이드·EDA 매뉴얼·과거 판정 사례를 Milvus Vector DB 지식베이스로 구축해 위반 유형별 컬렉션 지정 검색(Directed RAG)을 적용했고, 근거 출처 기반 신뢰도 스코어링으로 AI 비전공 설계자도 판단 근거를 검증할 수 있게 했습니다. rule 유형별 few-shot·structured output 프롬프트를 설계하고, EDA Tool·형상관리 연동은 MCP 서버로 표준화했으며, RTL 도메인 특화 경량 LLM 파인튜닝 PoC를 위반 사전 필터링에 일부 적용했습니다.

실과제 Lint Pilot에서 false violation 20%를 줄였고, 위반의 약 85%를 자동 1차 분석해 실리콘 버그 위험이 높은 위반에 리뷰를 집중, 블록당 리뷰 TAT를 약 60% 단축했습니다. 동일 접근을 CDC로 확장해 SFR-to-HW path의 약 95%를 noise로 자동 분류했습니다.

현업 설계자와 기술 요구사항을 정의하고 피드백 루프를 운영하며, CI/CD 파이프라인으로 폐쇄망 프로덕션에 배포해 서비스를 지속 개선했습니다. Agent Skill 공유 플랫폼은 500명 이상이 사용 중이며, 해외 연구소 3곳을 포함해 방법론과 플랫폼을 횡전개하고 현지 트레이닝을 수행했습니다.
```

## 수치 각주 (제출 전 확인)

| 수치 | 출처 | 상태 |
|---|---|---|
| false violation 20%↓ | 신입 지원서 제출본과 동일 (Lint Pilot) | ✅ 기존 제출 수치 — 그대로 유지 |
| SFR-to-HW path 95% noise 분류 | 신입 지원서 제출본과 동일 (CSR spec PoC) | ✅ 기존 제출 수치 — 그대로 유지 |
| 500명+ 사용 | 신입 지원서 제출본과 동일 (Skill 플랫폼) | ✅ 기존 제출 수치 — 그대로 유지 |
| 해외 연구소 3곳 횡전개 | 신입 지원서 제출본 (SoC 통합환경 건) | ⚠️ 원래 통합환경 실적 — "방법론과 플랫폼"으로 묶어 표현. 면접 답변 스크립트 필수 (방어노트 §5.1) |
| **전체 위반의 약 85% 자동 1차 분석** | 신규 | 🔴 [본인 확정 필요] 산정 정의 예: Pilot 블록에서 (deterministic+RAG로 분류 완료된 위반 건수)/(전체 위반 건수). 사내 pilot 로그로 소급 산정 가능한 값으로 조정할 것 |
| **블록당 리뷰 TAT 약 60% 단축** | 신규 | 🔴 [본인 확정 필요] 산정 정의 예: (기존 블록당 lint 리포트 1차 리뷰 소요시간) vs (Agent 1차 분석 후 고위험만 리뷰 시 소요시간). 설계자 피드백/본인 기록 기준으로 방어 가능한 값으로 조정할 것 |

- 🔴 두 개는 이전 신입 제출본에 없던 수치라 면접에서 단독 방어해야 함 — 방어노트 §4에 산정 로직 설계 가이드 있음. 실제 기억·기록과 안 맞으면 **숫자만 바꾸고 문장 구조는 유지**하면 됨.
- 기존 제출 수치 3종은 신입 지원서와 동일해야 함 (같은 회사 재지원 — 서류 대조 가능성).
